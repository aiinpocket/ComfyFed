# Phase 3.1 P2P Chunked Model Transfer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Federation members pull model files from each other in verified 64 MiB chunks under platform-issued short-lived grants, with upload bandwidth entering the receipt ledger — completing the last Phase 3 item.

**Architecture:** Agent sidecar hasher gains per-chunk SHA-256 (single pass with the whole-file hash); opted-in agents run a stdlib HTTP listener serving Range requests gated by platform-Ed25519-signed grants (TTL 10 min, single file/puller/seeder); the fetcher prefers a peer source before official URL → GCS; the platform tracks peer endpoints, issues grants, and books `p2p_upload` receipts (bytes, non-billable). Peer-only models (no official URL) become fetchable when an online seeder exists.

**Tech Stack:** Python stdlib http.server (agent listener — no new deps), existing Ed25519 signing conventions, Alembic + D1 migrations, Hono/D1 cloud parity, React web.

**Spec:** `docs/superpowers/specs/2026-09-12-comfyfed-spec.md` § "Phase 3.1 addendum: 成員間 P2P 分塊傳輸" — binding authority; read it first, every task.

## Global Constraints

- Security: grants are platform-signed over pipe-joined fields `grant_id|name|size_bytes|sha256|seeder_id|puller_id|expires_at` (reject any field containing `|`); TTL 600s; seeder verifies signature with its PINNED platform public key, expiry, seeder_id==self, name in local inventory — fail-closed 403, no anonymous path, no directory traversal (reuse existing path sanitization).
- Whole-file SHA-256 final verification ALWAYS runs after any P2P download; chunk hashes are an early-abort optimization only, never the trust root. CHUNK_SIZE = 64 MiB exactly (67108864).
- Fetch-phase billing rule unchanged: stage=fetching_models on every heartbeat during fetch; download time never billed.
- Agent protocol becomes 4; protocol ≤3 agents keep working, never receive peer fields, never get peer-only fetch_models entries.
- `peer_serve` defaults FALSE (worker sovereignty). Seeding is independent of worker disabled status.
- receipts: kind `p2p_upload` has billable=false, gpu_seconds=0, bytes=INTEGER>0, job_id NULL; only this kind may have NULL job_id. Payout/usage reports stay gpu_seconds-only; contributions gains bytes totals.
- Server/cloud behavior parity (shapes, error codes, signature format byte-identical).
- zh-TW first bilingual for all user-facing strings; no compromises incl. docs.
- Never run two pytest suites concurrently; all suites foreground. Alembic single revision `e1f2a3b4c5d6` (down `d0e1f2a3b4c5`); cloud single migration `0007_p2p.sql`.
- Commits end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 2: Agent chunked hashing

**Interfaces:** sidecar entries gain `chunk_sha256s: [hex,...]` computed in the SAME single read pass as the whole-file hash (one hasher per chunk boundary + one rolling total). ### Task 3: Server tracker + grant issuance + bandwidth booking

**Files:** Create `server/comfyfed_server/peer.py`; Modify app.py (mount), model_manifest.py (store chunk lists learned from reports — chunks stored on first report for a (name,size) whose whole-file hash matches consensus), agentws.py or workers.py (hash-report ingestion of chunks).
**Interfaces:**
- `POST /api/agent/peer-grant` (verify_agent): body `{name, size_bytes}`; platform checks requester lacks file (inventory), finds online workers whose inventory has (name,size) with consensus hash AND peer_url set; picks one (fewest active grants, then name); response `{grant: {grant_id, name, size_bytes, sha256, seeder_id, puller_id, expires_at, sig}, peer_url, chunk_sha256s}`; 404 `peer.no_seeder` when none.
- Grant signing helper `sign_grant(...)`/`verify_grant(...)` in security.py or peer.py — sig over pipe-joined fields per Global Constraints; issuance recorded in-memory `{grant_id: {seeder_id, name, size_bytes, expires_at, booked: bool}}` (persistence not required across restart — unbooked grants after restart are simply not billable; document).
- `POST /api/agent/peer-served` (verify_agent, seeder only): `{grant_id, bytes_served}` → validates grant exists, seeder matches, not already booked, bytes>0 and <= size_bytes*1.05 → inserts receipt kind p2p_upload (platform_sig per existing receipt signing convention; worker co-sign optional — follow how failed-receipts are signed today).
**Steps:** TDD grant issuance (no seeder, seeder choice, sig verifiable, expiry math), served booking (dedupe, bounds), chunk storage; full suite; commit.

### Task 4: Agent peer HTTP server

**Files:** Create `agent/comfyfed_agent/peerserve.py`; Modify config.py (`peer_serve: bool=False`, `peer_listen_port: int|None`, `peer_advertise_host: str|None` — coerce like max_fetch_gb), main.py (lifecycle start/stop with graceful shutdown), handshake/heartbeat to advertise URL when enabled.
**Interfaces:** ThreadingHTTPServer serving only `GET /peer/models/<name>` (name = manifest name `dir/file`, URL-encoded; sanitize each segment, resolve strictly inside a configured model dir via the same inventory index the agent already keeps). Auth: header `X-ComfyFed-Grant: <base64 json grant+sig>`; verify platform sig (pinned platform key for THAT platform — multi-platform agents: grant carries no platform id, so verify against every pinned platform key, accept if any matches AND seeder_id equals our worker id ON that platform), expiry, name match. Range: single `bytes=start-end` honored with 206 + Content-Range; no Range → 200 full file; If mismatch → 403 (no detail leaks). Log one line per grant, not per request.
**Steps:** TDD with real HTTP against a temp dir (small files): no-grant 403, tampered-sig 403, expired 403, wrong-seeder 403, traversal 403/404, correct Range bytes, full-file; shutdown closes listener; commit.

### Task 5: Agent fetcher peer path

**Files:** Modify `agent/comfyfed_agent/fetcher.py`, runner.py where fetch_models entries are consumed.
**Interfaces:** fetch order per model: if platform grants a peer (call peer-grant; 404 → skip to URL chain): pull chunks sequentially via Range (64 MiB), verify each against chunk_sha256s from the grant response when present (mismatch → abort peer source, fall to URL chain), append to `.part`; resume: on retry/re-grant, keep verified-complete chunks (recompute which chunks of `.part` are complete+valid by re-hashing local `.part` chunks before continuing). Grant expiry mid-transfer → request new grant, continue. Final whole-file SHA-256 verify ALWAYS (existing code path), atomic os.replace, rescan+report — all existing behavior. Cancel/shutdown abort+clean unchanged. Entries with `url: null, peer: true` (peer-only) skip the URL chain entirely; peer failure for those = fetch failure (existing failure handling: receipt 0.0 wall, job requeue per current rules).
**Steps:** TDD against a local test peer server (from Task 4's test helpers): happy path, chunk-mismatch fallback to URL, resume after simulated disconnect, peer-only failure path, cancel mid-pull; full suite; commit.
